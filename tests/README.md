# neurofedora-tests — QA harness for the `mhough/neurofedora` COPR

A clone-and-run test suite for every neurofedora package on Fedora 44+.
Drops onto a fresh machine, installs the COPR, installs every advertised
package, then runs four layers of automated checks:

| Layer | What it catches | How |
|---|---|---|
| **install** | "package isn't in the repo / has broken deps" | one `dnf install` transaction with `--skip-unavailable` |
| **smoke** | "binary segfaults on `--version`, Python import crashes" | per-package CLI/Python/lib/data check |
| **collisions** | "two packages own the same `/usr/bin/foo`" | pairwise `comm -12` over installed + repo file lists |
| **gui** | "GUI crashes within 5s of starting" | launches under `QT_QPA_PLATFORM=offscreen` or `xvfb-run`, asserts the process is still alive at the deadline |
| **pipelines** | "tool fails on real data" | synthesizes a tiny NIfTI/DICOM/DWI/mesh corpus, runs documented first-example commands, checks output |
| **static-qa** | "Fedora-compliance regression / missing .so dep / unresolved Requires" | per-host baseline of `rpmlint -i`, `ldd` scan, `dnf repoquery --whatprovides`; fails ONLY on counts that increased vs baseline |

Everything is **BATS-core**, with TAP output by default and JUnit XML for CI.
Tests **SKIP cleanly** when a package isn't installed so a partial install
never produces a wall of false failures.

## Quick start

```bash
git clone <this-repo> neurofedora-tests
cd neurofedora-tests

# First time: enable COPR + install every package + run all five layers
./run.sh

# Subsequent runs (skip the slow install pass):
./run.sh --no-install

# Just one layer:
bats smoke.bats              # per-package install check
bats collisions.bats         # file-conflict guard
bats gui.bats                # headless GUI startup
bats pipelines.bats          # real-data first-examples
bats static-qa.bats          # rpmlint + ldd + repoquery vs per-host baseline

# CI:
./run.sh --junit results/    # writes JUnit XML
./run.sh --tap   > out.tap   # raw TAP
```

### FSL FEEDS-style data layer

FSL's official FEEDS test dataset (which would include raw 4D DWI + bvecs +
bvals) lives on FSL's gitlab behind authentication, so the fetcher can't
pull it anonymously. Instead, `fetch-real-fixtures.sh` **detects a local FSL
install** (via `$FSLDIR` + common paths like `/usr/share/fsl`, `/opt/fsl`,
`~/fsl`, `/Applications/fsl`) and symlinks the standard data into
`fixtures/real/feeds/`. This unlocks:

- T1 templates at FSL's canonical 91×109×91 (2 mm) and 182×218×182 (1 mm)
  grids — distinct from nilearn's 99×117×95 cropping (both are valid
  MNI152 representations)
- Real diffusion-derived 3D scalar maps (FA) and 4D eigenvector fields (V1)
- A full brain-extraction pipeline test via T1 × brain_mask

If a real FEEDS install is present at `$FSLDIR/feeds/`, its `anat/`, `diff/`,
and `fmri/` subdirs are also symlinked — unlocking raw 4D DWI tests. To
install FEEDS itself: see FSL's docs at https://fsl.fmrib.ox.ac.uk/.

If FSL isn't installed, all `feeds/*` tests SKIP cleanly.

## Two-tier fixture model

- **Synthetic (`fixtures/*.nii.gz`)**: 32³ sphere, fully reproducible, no
  network. Used for *header / API smoke* — "does the tool parse this file
  and produce non-empty output". Always available.
- **Real (`fixtures/real/*.nii.gz`)**: MNI152 templates fetched via
  nilearn on first run, cached to `~/nilearn_data`. Used for *algorithmic
  smoke* — "does the tool produce sensible output on a real anatomical
  brain". Pipeline tests that reference `$FIX/real/*` SKIP cleanly when
  the fetcher hasn't run; `run.sh` calls it automatically once per box.

## What "smoke" means here

- **`cli`** — runs a representative command (`--version`, `--help`, etc.) and
  matches an expected output pattern. Catches "binary segfaults on startup"
  — exactly the class of bug the ITK-SNAP jsoncpp regression was.
- **`python`** — `python3 -c 'import X; print(X.__version__)'`. Catches missing
  `.so` deps, wrong Python ABI, and import-time crashes.
- **`lib`** — checks a representative `.so` or cmake config file exists. Cheap;
  verifies the install layout matches what downstream consumers expect.
- **`gui`** — Phase 1b adds real startup smoke: launches the binary headlessly
  (Qt apps via `QT_QPA_PLATFORM=offscreen`, anything else via `xvfb-run`),
  keeps it alive for N seconds, terminates it. Fail = crashed before the
  deadline; pass = stayed running OR exited cleanly. Logs go to
  `/tmp/neurofedora-gui-smoke/<pkg>.log`.
- **`data`** — checks the data directory exists.

## Pipelines (Phase 1)

`pipelines.tsv` carries documented "first example" invocations from each
tool's docs. The harness generates a small license-clean fixture corpus on
first run (`tests/fixtures/generate-fixtures.sh`, ~1 MB total) and exercises
the tool against it.

Each test gets:

- `$FIX` — absolute path to the fixtures directory
- `$TMP` — per-test scratch dir, automatically cleaned up

Adding a pipeline is one TSV row:

```
mrtrix3	mrinfo "$FIX/t1.nii.gz"	Dimensions:.*32 x 32 x 32
```

Then `./generate-pipelines.sh && ./run.sh --no-install`. Coverage is
intentionally additive — start with a few high-value tools, grow over time.

## File-conflict detection

`collisions.bats` runs `check-collisions.sh` in two modes:

- `--installed` — pairwise check across currently-installed packages.
  Fast. Catches "I have both X and Y on this machine and they fight."
- `--repo` — same check but over the COPR's repo metadata. Slower (one
  `dnf repoquery -l` per package). Catches conflicts **before** they
  block `dnf install`. This is what would have caught the
  itksnap × c3d × greedy bundling bug ahead of release.

Both modes filter shared-root directories (`/usr/lib`, `/usr/share/cmake`,
build-id trees) so only real file collisions surface.

## Why BATS, not `expect`

BATS-core is the de-facto bash test framework in 2026. TAP by default,
JUnit XML for CI ingestion (`bats --formatter junit`), parallel test
execution (`bats --jobs N`), packaged in Fedora as `bats`.

`expect` is overkill for a smoke layer that mostly asks "did this binary
install and respond to `--version`?". If a Phase 1 test ever needs to drive
an interactive prompt (e.g. a TUI without CLI args), reach for `pexpect`
then; for now everything is non-interactive.

## Known limitations

- Some packages don't have a conventional `--version`. Where the right
  invocation is unknown, the manifest uses `test -x` or `test -f` to smoke
  the install footprint. Phase 1 pipelines refine these incrementally.
- A handful of packages are commented out with `# WIP-F44:` — they are
  tracked-broken on F44 and excluded so the trunk run stays green.
- The install runs as a single `dnf` transaction with `--skip-unavailable`.
  A repo metadata gap surfaces as "Not installed" in the summary, not as a
  hard failure.

## Contributing

Every manifest TSV is the source of truth — bats files regenerate from
them. Patches that add a row + regenerate the bats output are the right
shape. Run `./run.sh --no-install` before opening a PR; only **regressions**
should turn the suite red.
